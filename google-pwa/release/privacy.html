Privacy information

VARKA Release Automation is an owner-operated deployment tool. This page describes how the release helper and workflow handle Google authorization and script data.

Access and purpose

The Google OAuth permissions script.projects and script.deployments are used to read the configured Apps Script project and deployed version, preserve original files, update the four managed files, and update the same deployment. The release helper does not request direct access to spreadsheets, Gmail, or Drive files. The deployed inventory application's separate permissions are unchanged.

Credentials and storage

The downloaded Desktop OAuth client JSON remains on the owner's computer outside the repository. Setup uses a temporary 127.0.0.1 callback with state validation and PKCE. The helper sends the OAuth client ID, client secret, and refresh token directly to the repository's github-pages environment secrets through GitHub CLI. It does not print or save the resulting tokens to another file.

The GitHub Actions deployment step uses those secrets to communicate with Google's OAuth and Apps Script APIs. Script source is processed in the release runner's memory. The release scripts withhold remote source, credentials, and raw Google error bodies from their logs. Credentials and private backend source are excluded from the public GitHub Pages artifact.

Sharing and retention

Google processes authorization and Apps Script API requests. GitHub stores the environment secrets and runs the release. The owner controls the original downloaded JSON and the configured GitHub secrets until they delete or replace them. The temporary local callback server closes when setup completes or times out. The release helper contains no advertising, sale-of-data, or analytics integration.

Revoking access

The owner can revoke the OAuth application's access in their Google Account connections, remove the three Google OAuth environment secrets in GitHub, and remove the local client JSON. Revocation prevents future authorized releases; it does not undo code versions or releases already deployed.

For setup questions, use the release guide or project support. Do not include credentials, private script source, workbook exports, or inventory details in a public issue.
